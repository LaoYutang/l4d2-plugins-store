# 地图待办队列切图与章节重连开发计划

> 状态：已实现为 1.1.0；2026-10-07。仓库编译与离线回归通过，实服验收待完成。
> 开发基线：`l4d2_map_queue.sp` 1.0.6，仓库提交 `efa83f8`。
> 用户要求：保留现有自动续队列与切图功能，将 `!mapnext` 的统计消息及返回大厅逻辑作为兜底，覆盖常规终局事件未触发或原切图请求未生效的情况；同时处理章节重连期间队列被停止的问题。
> 本计划已按用户确认的“保留原功能、mapnext 作为兜底”实施。源码、SMX、配置和交付文档同步更新；未部署实服。

## 1. 已核对的行为与问题边界

- `!mapnext` 由 `l4d2_map_vote.sp` 注册。投票通过仅调用 `MC_SetNextMap` 设置目标，真正切图由 `map_changer.sp` 执行。
- `map_changer` 默认 `mapchanger_finale_change_type=12`，即 `4 | 8`：在 `StatsCrawlMsg` 发出后切图，并在统计流程准备返回大厅时拦截 `DisconnectToLobby`。包含 `8` 不表示默认等待统计全部播放完。
- 目前待办队列依赖 `finale_vehicle_leaving` 或 `finale_win`，默认从先收到的事件开始等待 3 秒，再经过 0.1 秒定时器调用 `ForceChangeLevel`。没有这两个事件时不会自动推进。
- 用户通过“立即启动队列”进入 Freezing Point，进行到后续章节时发现队列为 `stopped`，仍有三项待办，面板没有“跳过当前”。面板仅在插件返回 `active` 时显示该按钮；这说明需要排查运行状态中断，不能把问题归结为按钮显示。
- 当前已有地图序号保护：断开回调预约下一帧检查，`OnMapEnd` 增加序号，旧检查应失效。正常 SourceMod 章节切换会产生客户端断开回调；这条机制本身不能证明实服停止的根因。
- 插件重载、确认空服、禁用或切换到不支持的模式都可能停止队列并把未完成项放回队首。实际停止来源尚未获得实服日志确认，本计划不把某个猜测写成已证实根因。

对照源码：

- [投票下一张地图](https://github.com/LaoYutang/l4d2-plugins-dev/blob/efa83f8/addons/sourcemod/scripting/l4d2_map_vote.sp)：`NextMap_Handler`。
- [mapnext 切图实现](https://github.com/LaoYutang/l4d2-plugins-dev/blob/efa83f8/addons/sourcemod/scripting/map_changer.sp)：`umStatsCrawlMsg`、`umStatsCrawlMsgPost`、`umDisconnectToLobby`、`ChangeLevel`。
- [待办队列](left4dead2/addons/sourcemod/scripting/l4d2_map_queue.sp)：`TryCompleteCampaign`、`Timer_StartNextQueueItem`、`SwitchToActiveMap`、`Frame_CheckForEmptyServer`、`LoadQueueState`。

## 2. 本阶段范围

1. 保留 `finale_win` / `finale_vehicle_leaving` 主触发、现有延迟及 `ForceChangeLevel` 切图功能，在待办队列内部增加 `mapnext` 的统计消息和返回大厅兜底。队列独立运行，不新增对 `map_changer` 的必选依赖。
2. 修正章节切换与玩家重连时的空服判断，正常章节过图保留当前项和运行状态。
3. 为通关去重、切图请求、目标加载和停止原因建立日志与回归验收。

继续保留现有投票、RCON、列表协议和队列命令语义。不修改 `l4d2_map_vote`、`map_changer`、旧插件或面板。面板已有的“执行中 → 跳过当前”应随着插件正确保留 `active` 恢复；本阶段不通过额外显示按钮掩盖状态丢失。

## 3. 自动切图的触发点与优先级

| 输入 | 处理方式 |
| --- | --- |
| `finale_win` / `finale_vehicle_leaving` | 保留现有主触发。首个有效事件接受本次通关，按 `l4d2_map_queue_change_delay` 等待，默认 3 秒，再沿用现有切图流程。 |
| `StatsCrawlMsg` 成功发出 | 补充兜底。原终局事件未触发、没有接受本次通关时，独立接受通关并在下一帧进入兜底切图。主流程已有有效延迟或切图请求时只记录上下文，不提前计时、重复出队或发第二条命令。 |
| `DisconnectToLobby` | 返回大厅兜底。已有可信通关上下文、队列允许续播且目标准备成功时，拦截返回大厅并完成同一次切图；复用现有待切目标。 |
| 普通章节过图 / 团灭 / 重开 | 不视为完整战役成功，不消费当前项或下一项。 |
| 管理员 `run` / 运行中的 `skip` | 保留主动切图行为，不等待统计消息。暂停恢复和停止状态的 `skip` 继续遵守现有语义。 |

顺序原则：现有事件路径优先；统计消息补足缺失触发；大厅消息防止尚未完成的切图被返回大厅打断。多个来源进入统一的通关记账与切换流程，不分别维护三份队列推进逻辑。

### 3.1 保留现有主流程

1. 保留两个 `finale_*` 事件的通关处理入口、合作类模式/终局地图判断及已有命令语义，不改为仅记录辅助上下文。
2. 首次接受通关后按现有规则完成活动项、保存队列；有下一项时进入 `delay`，保留 `l4d2_map_queue_change_delay=3.0` 默认值和起算点。
3. 延迟到期后沿用现有 0.1 秒切图调度及 `ForceChangeLevel` 后端。暂停或队列耗尽仍按现有规则停止，不自动恢复队列。
4. 主流程健康等待时，后到的统计消息不得把已有 3 秒等待改成下一帧切图，也不得重新开始计时。

### 3.2 统计消息补充兜底

1. 注册 `StatsCrawlMsg` 的普通观察与 post 回调。消息到来时只记录地图序号和终局上下文，不在消息钩子里发送聊天、用户消息或调用切图 SDK。
2. post 回调确认 `sent=true` 后预约下一帧。捕获地图序号与操作代次，执行时重新检查插件启用状态、合作类模式、终局地图、队列状态和代次。
3. 没有收到原终局事件、也没有接受本图通关时，通过统一入口接受一次通关并保存队列。有下一项则采用 `mapnext` 的兜底后端；不要求提前收到 `finale_*` 或 `trigger_finale` 的 `FinaleStart` 输出。
4. 仅由统计兜底启动的切换默认在消息发出后的下一帧请求，不额外套用主事件路径的 3 秒延迟。该规则不修改现有延迟配置的语义。
5. 主流程已有有效延迟或正在等待切图确认时不抢跑，只保存兜底上下文。主请求确认超时后，才允许有限的兜底重试；复用同一个已预留目标，不再接受通关或出队。
6. `paused` 完成当前项后停止，队列耗尽也停止。手动停止、清空、禁用或取消后的迟到消息不得重新启动队列。

统计消息被其他插件拦截、`sent=false` 时不直接执行统计兜底；观察到的统计上下文可以供返回大厅兜底使用。消息回调中的 `BfRead` 和接收者数组不能直接留给下一帧使用，所需数据必须复制。

### 3.3 返回大厅兜底

- 生命周期内注册 `DisconnectToLobby` 拦截，通过队列状态和本图上下文决定是否介入，不只依靠收到统计消息后才安装拦截。
- 通关记账与自动推进分开：`running/armed/paused` 都可接受可信的本图通关一次；`paused` 完成当前项后停止，队列耗尽也停止，均放行正常大厅流程。
- 自动切图拦截要求“当前地图为终局 + 合作类模式 + 本图已观察到统计或终局成功上下文 + 队列允许续播”，且存在已预留未加载的有效目标，或能从待办准备有效下一项。最后一项已预留、待办数量变为 0 时，也要保护这次尚未完成的切图。
- 主流程仍在配置延迟中但引擎已经准备返回大厅时，兜底可结束剩余延迟并切同一项；这是防止玩家被送回大厅的兜底条件，不是统计消息到来即提前切图。
- 已有请求正在确认时，先拦截大厅、保留上下文并复用请求，不立即发第二条切图命令。确认超时后按统一失败流程最多切换一次兜底后端。主流程和兜底共享切换标记，不能同时发出不同目标。
- 在返回 `Plugin_Handled` 前，必须完成可复用的目标准备与持久化；目标无效、保存失败、没有成功上下文时放行原消息并写明原因。
- 切图和通知都在消息钩子退出后执行。已拦截的大厅消息不能因后续切图失败而永久丢失：实现时保存必要的消息内容与玩家身份，有限重试失败后可在下一帧恢复该大厅通知，穿透本插件钩子，避免循环拦截。
- 实施前核对 `DisconnectToLobby` 的真实消息格式并验证恢复路径；不能把“取消钩子”当成已经恢复被拦截的那条消息。

若三方地图连统计消息与终局成功上下文都不产生，仅有玩家退出或返回大厅，不猜测其已通关。无法被引擎识别为终局的地图另行记录诊断，不承诺这一方案覆盖所有异常地图。

## 4. 切图后端、去重和加载确认

### 4.1 切图后端

- 现有事件主流程及管理员主动切图继续使用 `ForceChangeLevel`，不整体替换当前后端或更改正常切图时机。
- 新增兜底路径与 `map_changer` 一致：可用时调用可选 native `L4D2_ChangeLevel`，否则执行经过地图名校验的 `changelevel` 服务器命令。
- 原请求未开始换图时，最多使用兜底后端重试一次；只改变请求方式，复用目标及队列快照，不再次消费待办。
- 不把设置 `MC_SetNextMap` 当作队列切图成功；队列自行持有目标并发起切图。
- 兜底 SDK/native 调用避开用户消息钩子，下一帧调用；服务器命令仅接受与现有机器协议兼容的地图代码，避免命令拼接问题。
- 保留空服 RCON `run` / `skip` 的直接发起路径，不让它依赖可能因服务器休眠而停摆的游戏定时器。

### 4.2 单次切换与队列保存

- 使用地图序号、队列操作代次、本图通关接受标记和待切目标，约束同一次通关只能处理一次。
- 统计消息可能按接收玩家多次出现；重复 post、两个终局事件和大厅消息同时到来，仍只完成一个当前项、预留一个下一项。
- 队列快照提交成功后才更新通关接受标记或发起切图。保存失败保留原项目顺序，记录停止原因，不发送切图命令。
- 下一项成为 `active` 表示已预留进入该战役，不表示该战役已完成。切换未确认期间，禁止旧地图的统计或终局消息完成这个新项。
- `clear`、`pause`、`skip`、禁用和手动换图必须取消或替代过期请求；回调不能凭旧目标继续切图。队首在延迟期间被修改时，以最新有效请求为准。
- 本图已观察到可信通关信号后才执行 `runafter` 时，复用仍有效的本图上下文：有原终局事件则走现有事件路径，仅有统计消息则走统计兜底；不得因为消息已发出而一直等待下一次事件。团灭重开时清除旧通关上下文，不能把上一回合信号用于新回合。
- 保持 `stopped/armed/running/delay/paused` 和 `MQ_LIST schema=1` 的对外协议。切图确认、通关上下文和重连保护使用内部字段，不向面板添加不认识的状态。

### 4.3 切图确认与失败处理

- 切图命令发出只记录“请求已发出”；下一次 `OnMapStart` 校验实际地图等于待切目标后，才记录“目标已加载”。
- 普通章节继续时不应用这个首次进入目标的校验，不因为进入第二、第三章而判断当前项失效。
- 请求发出后旧图仍在运行、10 秒内没有开始换图时，重新检查目标、状态和代次，最多再发一次兜底请求。首次走 `ForceChangeLevel` 时改用 `mapnext` 后端；首次已走兜底时也只允许一次重试，不形成两个各自重试的流程。一旦 `OnMapEnd` 表明换图已开始，不因加载较慢重复发命令。
- 第二次请求仍未开始换图时，停止并把未进入的活动项放回队首一次，保留其他待办。不同目标的外部换图明确取消本次确认；不把外部地图当作请求成功。
- 管理员手动换图后的队列延续规则沿用现有安装说明，不追加“通关战役必须属于原活动项”的新限制。

## 5. 章节切换与空服保护

1. 保留现有地图序号过滤，同时增加明确的地图卸载/加载阶段。旧地图产生的断开检查和切图回调不能在新图生效。
2. 空服判断使用“已连接的真人”数量；已连接但仍在加载的玩家不算空服。游戏内投票的玩家筛选仍按已进入游戏处理。
3. 新图开始后提供默认 30 秒的重连缓冲。保护期间保留 `running`、`paused` 或 `armed` 及对应当前项，不因为某一帧 `IsClientInGame()` 全为 false 回退队列。
4. 缓冲到期时重新检查已连接真人；仍无真人才停止，并把未完成项放回队首一次。玩家完成进服后结束启动保护，后续真正最后一名真人离服仍能停止队列。
5. 重连期限使用实际经过时间，不能只用可能因无人而不推进的模拟游戏时间。通过现有 Left4DHooks 的 `L4D_OnServerHibernationUpdate` 观察休眠/唤醒，结合进服、断开和队列命令入口复查期限；不修改服务器休眠配置。完全休眠且没有回调时不承诺定时器会按时运行，但唤醒或查询状态的第一个入口必须先结算已过期保护，不能继续向面板报告一个过期的运行状态。
6. 终局自动切图发起后，在进入新图的过程中复用同一套保护，不再把正常过图断开当成玩家主动离服。
7. 模式校验在依赖与配置完成后确认，启动阶段未知模式暂缓判断；真正切换为不支持的模式仍停止队列。
8. 插件重载与服务器重启继续保留“未完成项回队首并停止”的现有恢复规则，明确记录重载/读档来源，便于与普通章节过图区分。

## 6. 配置与诊断

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `l4d2_map_queue_change_delay` | `3.0` | 保留原键、默认值和现有事件路径的等待起点；不改为统计消息计时。统计兜底独立在下一帧调度。 |
| `l4d2_map_queue_reconnect_grace` | `30.0` | 新增换图后重连缓冲秒数，限制为 1～120 秒。 |
| `l4d2_map_queue_enable` / `l4d2_map_queue_vote_time` | 沿用现有值 | 启用与投票语义保持一致。 |

保留现有 `change_delay` 配置和默认值，不要求管理员改为 0。新增重连缓冲配置，并在安装说明中分别写明现有事件延迟、统计兜底下一帧及返回大厅紧急兜底的时机；已有配置继续控制原事件路径。

关键日志默认写入 SourceMod 日志，不依赖有人在线时的聊天提示，记录：

- 原终局事件、统计兜底或大厅兜底的来源，是否复用已有请求，以及当前地图、地图序号和操作代次。
- 通关接受、待切目标、采用的后端、请求次数和目标加载确认。
- 换图重连保护开始、已连接/已进游戏真人数量、保护结束。
- 所有停止路径及原因：真正空服、模式不支持、插件禁用/卸载、读档恢复、地图失效、持久化失败、切图未确认。

`sm_mq status` 与 `MQ_LIST` 的字段保持现有格式，详细诊断写日志，避免破坏面板严格解析。战役目录读取暂时失败时不先清空有效缓存、再把目标误判为地图不存在；明确区分暂时读取失败和 BSP 实际失效。

## 7. 实施顺序

1. 建立统一的通关接受、切换代次和目标确认流程，覆盖重复信号、取消及保存失败。
2. 保留原终局事件主流程，接入统计消息与大厅兜底；明确已有延迟/待确认请求的优先级，验证统计信号不会抢跑主流程。
3. 保留现有 `ForceChangeLevel` 后端，新增可选 native/服务器命令兜底，接入新图加载确认和共享的有限重试。
4. 接入章节重连保护、连接人数统计、稳定的模式判断和所有停止路径日志。
5. 更新配置、版本、安装说明与验收文档，验证原有命令和面板协议。
6. 用项目现有编译器以 `-E` 编译；必要回归通过后更新未压缩 `dist`，生成并核对交付 ZIP，再提交和推送实施改动。

1.1.0 已完成上述实现与仓库验证，交付包由 `tools/build_map_queue.py` 编译、生成并逐文件校验；实服验收仍按下述矩阵进行。

## 8. 验收矩阵

离线回归应执行真实 SourcePawn 回调，通过 native fixture 控制消息送达、连接状态、地图载入和保存结果，断言实际队列、请求次数与状态；不能仅检查源码字符串存在。

| 场景 | 必须满足的结果 |
| --- | --- |
| 官方战役正常终局 | 原终局事件触发后按现有配置等待，默认 3 秒，再沿用 0.1 秒调度和 `ForceChangeLevel`；统计消息不抢跑、不重新计时。 |
| 缺少两个 `finale_*` 事件，但有统计消息 | 统计兜底在消息发出后的下一帧请求下一项，不依赖原事件，也不消费两次。 |
| 统计缺失/被拦截，但有终局上下文和大厅消息 | 大厅兜底进入同一项，不依赖统计 post 成功。 |
| 原事件延迟中收到统计消息、随后准备返回大厅 | 统计不缩短原延迟；大厅兜底必要时结束剩余延迟，复用同一目标，只推进一次。 |
| 原流程已发出请求，又收到统计或大厅消息 | 不立即重复请求；只有确认超时才允许一次兜底重试。 |
| 仅统计兜底触发后又收到大厅消息 | 复用请求，完成/出队各一次，不另选目标。 |
| 多玩家分别收到统计、重复终局事件 | 不重复消费，包含同名重复待办。 |
| 团灭、原地重开、非通关退出 | 不误记战役成功，不消费待办。 |
| 同战役第一章到后续章节，玩家断开再重连 | 当前项与运行状态保留，进服后面板仍显示“跳过当前”。 |
| 玩家加载超过 30 秒，但已建立连接 | 保留队列，连接存在时不判空服。 |
| 换图后确实无人、超过缓冲期 | 停止并回队首一次，日志可确认原因；覆盖休眠。 |
| 旧图回调晚到、等待期间 `pause/clear/skip` | 旧请求失效，不发生意外切图或重复回队首。 |
| 统计消息已发出后执行 `runafter`、随后团灭重开 | 可用的本图上下文正常触发；旧回合上下文不得在重开后生效。 |
| 延迟期间队首被删除/插队、管理员外部换图 | 正确取消或替代旧请求，列表顺序和既有外部换图规则保持一致。 |
| 目标 BSP 失效、目录暂时读取失败、保存失败 | 区分原因，保留待办，不把失败当成成功。 |
| 原请求发出后仍未开始换图 | 超时后以 `mapnext` 后端兜底一次，失败后明确停止；目标无损恢复，不再次出队。 |
| 已开始换图但加载较慢 | 不重复切图；新图加载确认正确。 |
| 大厅消息已拦截，随后切图失败 | 不永久困在旧图，恢复大厅路径无循环、无过期玩家误发送。 |
| 有/无 `L4D2_ChangeLevel` 插件 | 原主后端保持可用；两条兜底后端均可用，加载/卸载可选依赖后仍正确选择。 |
| 空服 RCON `run/skip` | 保留直接发起行为，不等待休眠定时器。 |
| 同时启用/未启用 `map_changer` | 队列独立可用；接管期间不会产生双方重复切图，结束后恢复最新配置。 |
| 插件重载、禁用和服务器重启 | 按已有规则恢复待办，停止来源有明确日志。 |

实服重点验收 Freezing Point 从第一章连续进入后续章节、缺常规终局事件的三方战役、长加载、真正空服和中途跳过。记录实际版本、配置、事件顺序、状态与面板刷新结果；离线和编译通过不等于实服验收通过。

## 9. 1.1.0 实施与验证结果

- 主终局事件、默认 3 秒等待、0.1 秒调度及 ForceChangeLevel 保留；统计只填补缺失触发，已接受通关但丢失调度的路径也可使用同一个目标兜底。
- 兜底切图由统计 post 后下一帧或大厅拦截后的下一帧发起。暂停时只静默保存通关、不准备目标，且保护外部插件在本插件 post 前卸载地图的边界。待确认请求不因新信号立即重复发送，10 秒未开始换图才最多再请求一次；开始加载后取消重试。
- 大厅消息不按猜测的理由字符串解码，保留完整 BitBuf 字节、原可靠性标志和接收者 serial；失败后恢复原通知并绕过消息钩子。空载荷支持，超过 256 字节或缓冲上限的消息直接放行，真实客户端消息仍待实服验收。
- 目录 SDK 暂不可读或返回空目录时保留有效缓存；BSP 存在性仍实时校验。启动阶段未知模式通过后续检查确认，不直接当作不支持的模式停止。
- 9 组生产 SourcePawn 字节码回归、91 项断言通过，编译使用项目编译器及 -E，零警告。详细记录见 [验证记录](l4d2_map_queue_validation.md)，安装说明见 [README](README.md)。
- 真实 Freezing Point、终局统计/大厅消息、章节网络重连、休眠与 SDK 切图尚未获得实服验证。原报告停止的确切来源也仍需新日志确认。
